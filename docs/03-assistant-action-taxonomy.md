# Coop · 人与事的持续盯防

> 替你盯人和事：一个回路，多种触发  
> 对应 canvas：`canvas-sources/assistant-action-taxonomy-people-matters.canvas.tsx`

## 概述

「盯进展」不是单个动作，而是一条通用的**补缺口派生回路**。所有类似动作都走同一条回路，只是被不同的「缺口」触发。

缺口的来源只有两个：**事的健康度** 与 **人通道的状态**。

| 统计 | 数量 |
|------|------|
| 统一回路 | 1 |
| 事侧缺口类型 | 7 |
| 人侧缺口类型 | 3 |
| 横切判断（找谁·何时·怎么说） | 3 |

---

## 统一回路：盯进展是它的一个实例

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 侦测 Sense | 可观测信号触发：发现某个缺口 |
| 2 | 派生 Derive | 生成一个要找人推进的子事 |
| 3 | 拟稿 Draft | 建议对象 + 内容（找谁·怎么说） |
| 4 | 你确认·发出 | 用户确认后才发出 |
| 5 | 收敛 Close | 回应是否有效闭合 → 完成子事 + 更新母事 |

### 实例 · 催更新

侦测「churn 数据：增长群 2 天没更新」→ 派生子事「问增长群」→ 拟稿「找增长负责人 · 问『churn 口径今天几点能出』」→ 你确认后发出 → 跟踪回复延迟和内容是否含有效数 → 有效则完成子事「催更新」并更新母事「Pony 1on1 准备」；超时 / 无效则升级（换人、换措辞、或上报你）。

## 事侧：推进型事的 7 类缺口

一个事相对其目标，只会因这几种偏差而不健康推进。每类缺口对应一个派生子事 + 一条明确的闭合判据。

| 缺口类型 | 触发信号（可观测） | 派生子事 | 闭合判据 |
|---------|-------------------|---------|---------|
| 缺信息 · 沉默 | 该更新却 N 天无新消息 / 无动静 | 催更新（盯进展） | 拿到有效进度更新 |
| 缺明确 | 目标 / 范围 / 标准 / 负责人 / 期限不清 | 求澄清 | 关键字段被补全 |
| 缺推力 | 被前置依赖或某人阻塞 | 推依赖 · 解卡 | 阻塞解除、可继续 |
| 缺决断 | 卡在需要拍板才能继续 | 请决策（拟好选项） | 拍板产出，事可继续 |
| 有碰撞 | 撞期 / 抢资源 / 两方口径不一 | 协调对齐 | 冲突消解、口径一致 |
| 临期限 | deadline 临近且未达成 | 赶节点 · 提醒 | 按期完成或重新排期 |
| 待验收 | 声称完成但未确认 | 验收闭环 | 确认确实 done |

## 人侧：人通道的 3 类缺口

最终执行和完成事的是人。人通道的状态本身也会出缺口——同样用一个派生子事来补。

| 缺口类型 | 触发信号（可观测） | 派生子事 | 闭合判据 |
|---------|-------------------|---------|---------|
| 通道冷却 | 触达冷却 ≥ N 天，长期无互动 | 维系触达 | 重新建立联系 |
| 承诺悬空 | 答应了某事，到点没动作 | 追承诺 | 兑现或重新约定 |
| 信号异常 | 响应速度 / 语气明显变化 | 关心 + 择时修复 | 状态回暖 / 找到症结 |

「追承诺」与「催更新」是同一回路的两个入口：一个从**事**进（事没动静），一个从**人**进（人欠你的没兑现）。

## 横切层：每个派生动作都要替你决定的三件事

这是「拟稿」里真正有价值、也是你确认前要看的内容——不只是发什么，而是对谁、什么时候、怎么说。

| 维度 | 说明 |
|------|------|
| 找谁（对象） | 人-事匹配：谁有答案、谁是瓶颈、谁能拍板 |
| 何时（择时） | 读人状态，挑对方最可能积极响应的时机 |
| 怎么说（措辞） | 按信任 / 情绪 / 关系成本给措辞 + 置信度 |

---

## 推进型事 vs 存续型事

| 类型 | 价值在 | 缺口表现 | 闭合判据 |
|------|--------|---------|---------|
| 推进型（telic） | 结果 | 没进展、被卡、临期 | 事完成 / 节点达成 |
| 存续型（atelic） | 过程 | 太久没投入、温度下降 | 恢复节奏 |

上面 7 类缺口主要对应推进型事。存续型事（如家人陪伴、关系维系）的缺口是「太久没投入」，人侧的「维系触达」就是它的盯防。

## 收敛与升级

每个派生子事都必须有明确的闭合判据，靠两路信号判断：

- **回复延迟**：对方多久没回
- **内容质量**：回复是否足以闭合这个子事

| 结果 | 动作 |
|------|------|
| 有效 | 完成子事 + 把更新回收进母事 |
| 无效 / 超时 | 升级：换人、换措辞、或交还给你定 |

子事永远向母事汇报，不留悬空。

## 派生治理：置信度预算 + 图吸收深度

该被限制的不是「深度」本身，而是「自动收敛」能否被信任。子事闭合 ⇒ 母事推进 这个推断每多一跳就乘一次正确率 p，顶层状态可信度 ≈ p^层数。

### 关键数字

| 指标 | 值 | 说明 |
|------|-----|------|
| 默认呈现 | 2 层 | 主事 + 推进它的子事，最优 |
| 自动派生硬顶 | 3 层 | 子事自己停滞时惰性展开 |
| 活跃叶子数 / 顶层事 | ≤ 7 | 一眼能扫完 |
| 绝对红线 | 5 层 | 越线强制提示重构 |

### 顶层状态可信度 vs 派生层数

（示意，取每跳推断正确率 p≈0.85）

| 派生层数 | 顶层可信度 | 含义 |
|---------|-----------|------|
| 2 层 | ~0.72 | 理想：主事 + 推进它的子事 |
| 3 层 | ~0.61 | 可接受：子事自己停滞时惰性展开 |
| 4 层 | ~0.52 | 已近抛硬币 → 应横向拆成并列事 |
| 5 层 | ~0.44 | 红线：越线强制重构 |

### 五条治理规则

1. 自动派生硬顶 3 层 · 默认呈现 2 层：第 3 层折叠、按需展开
2. 第 3 层惰性生成：仅当某子事自己停滞、需要它自己的补缺口回路时才生成
3. 想触第 4 层 → 不 nest，报警：提示「顶层事框错了高度」，建议横向拆成图中并列 peer（你确认后执行）
4. 复杂度阀门挂在活跃叶子数上：每个顶层事 open frontier ≤ 7 + 限扇出
5. 5 层为绝对红线：含人工手动，越线即强制提示重构

想往更深 nest 时，往往是顶层事「框错了高度」。正确做法是把它横向拆成图中并列的 peer 事——用图横向吸收掉本该靠深度纵向承载的复杂度。

## 边界

- 所有「侦测」只在可观测信号上成立（消息流、文档、日历）——看不见的要么标注低置信、要么靠主动探询补
- 所有要找人发的动作都先经你确认：每次催、问都在消耗关系，措辞和频率由你掌控
