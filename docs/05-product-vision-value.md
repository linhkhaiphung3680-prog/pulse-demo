## 为什么叫 Coop

模型收敛到一个词——**协同**。不是 AI 替你做，是**协同地把事推向它该在的状态**。

---

## 管理者：他真正怕的是什么

他不会用产品内部术语。他的痛是——**把控感在流失**：事没声音了、怕漏了重要的、某个人不对劲却说不清、卡住了不知道怎么解。

而每一种痛，他现在都靠**亲自去盯、去问、去开会、去揣摩**来对冲——这持续烧掉他最稀缺的**注意力和精力**。

Coop 的价值，就是把「维持把控感」这笔隐形开销，降到接近零。

---

## 管理者的心声 → 现状的代价 → Coop 的解脱

| 他心里其实在说 | 现状下他怎么扛（烧掉什么） | Coop 怎么让这份消耗消失 |
|--------------|-------------------------|----------------------|
| 「这件事最近没声音了，到哪了？」 | 得自己去问、开个会、催一下——烧时间，催本身还伤信任 | 没声音时 Coop 替你盯着；真停滞/有风险才出声。把控感来自「我知道我会被告知」，而不是「我得亲自盯」 |
| 「几十件事并行，我怕漏了重要的。」 | 靠脑子记、靠 to-do、靠不停切换 check——心智负荷 + 怕遗漏的焦虑 | 所有事在一处被守着，只把「需要你的」顶上来，其余替你 hold |
| 「李四最近积极性不高……说不上来。」 | 模糊的不安，怕是错觉，又怕贸然找他谈谈错 | 把你的直觉变清楚：「自晋升被跳过后，他在这几件事上的投入和响应在下降」。低置信时只轻提示，绝不替你下定论 |
| 「事情好像没在正确地推进。」 | 感觉不对却找不到抓手，只能广撒网式过问 | 精准点出哪些事推过头了、哪些在空转，而不是让你全面巡查 |
| 「天天开会发消息，到底有没有实质进展？」 | 在信息洪流里分不清信号与噪声 | 每条消息已被判好「让这件事更明确了，还是在原地打转」。你看的是进展，不是消息 |
| 「这事卡住了，可我不清楚卡在哪、怎么解。」 | 召集相关人开会摸排，耗时且常摸不到真因 | 诊断卡点在信息还是在人，并给出解法路径。摸排和判断它做掉，决策留给你 |

**一句话**：Coop 把他每天花在「维持把控感」上的注意力和精力**省下来**，还给只有他能做的判断。

## 产品目标

### 北极星目标

让人重新拿回**把控感**——而且**不靠亲自去盯**；把维持把控的注意力/精力开销降到接近零，余力还给「需要人的判断与在场」。

### 支撑目标

| 目标 | 说明 |
|------|------|
| 把控感不靠亲自盯 | Coop 替你维持对所有事的感知，只在需要你时出声 |
| 让事被正确地推动 | 该明确的明确、该存续的存续；停滞与失控提前冒泡 |
| 把模糊的人感觉看清 | 「某人不对劲」这种直觉，变成可判断、可行动的清晰 |
| 个人 ↔ 组织 同一引擎 | 家与公司是同一套人/事/消息，切换的只是参与方 |

## 个人用户：他真正怕的是什么

他的痛是——心里总有一堆**放不下的牵挂和怕辜负**：怕冷落了人、怕漏了答应的事、怕日子白过、陪家人时又走神。

如果说管理者怕的是**失控**，个人用户怕的是**辜负**。

---

## 个人用户的心声 → 现状的代价 → Coop 的解脱

| 他心里其实在说 | 现状下他怎么扛（耗着什么） | Coop 怎么让这份消耗消失 |
|--------------|-------------------------|----------------------|
| 「一打开手机就被消息拽走，回着回着忘了自己本来要干嘛。」 | 注意力被劫持 + 本来想做的事又没做的焦虑 | 打开看到的是「今天我本来要做的几件事」，消息被归到各自的事里 |
| 「好久没联系 XX 了，心里一直惦记，又老忘、老拖。」 | 持续的牵挂占着心，还总错过该联系的时机 | Coop 替你记着谁该联系、什么时候是好时机 |
| 「我想变好/想做成那件事，可每天过完，也不知道有没有靠近一点。」 | 方向感缺失带来的空耗感和自我怀疑 | 你在意的那件长期的事，它帮你看见「今天有没有往前挪一点」 |
| 「陪家人的时候还在想工作，结果两头都没顾好。」 | 分心拉低了陪伴质量，事后还自责 | 陪伴时，工作的事它替你盯着、绝不打扰 |
| 「答应别人的事我怕漏了，显得不靠谱。」 | 怕失信的焦虑 + 反复在脑子里核对 | 你答应别人的、别人答应你的，都挂在对应的事上，到点提醒你 |
| 「AI 工具我不敢全信，怕它擅自发了不该发的、瞎给建议。」 | 不敢放手，于是工具没真正帮你减负 | 拿不准就问你，对外的话默认你确认了才发 |

**一句话**：Coop 把「惦记着、怕漏了、怕辜负」的心理负担**替你卸下来**。

## 场景 · 围绕「省心与把控」

### 管理者的一上午

| 时刻 | 体验 | 解脱 |
|------|------|------|
| 打开 | 「本周 6 件事需要你出手」，其余它替你盯着 | 把控感回来 |
| 新能源并购 | 「没声音 9 天了，其实卡在对方法务有顾虑」 | 停滞自动冒泡 |
| 预警 | 「你和投资部对交付时间的口径不一致」 | 提前知道要出事 |
| 怎么解 | 「真因不是信息，是人——给你一版对齐对方的话」 | 不用自己摸排 |
| 拿不准处 | 某处 AI 没把握 → 交回你定，而非硬猜 | 它知道分寸 |
| 某 BU 翻车 | 自动反推「这对集团全年目标的敞口」 | 牵一发知全身 |

### 个人用户的一天

| 时刻 | 体验 | 解脱 |
|------|------|------|
| 打开 | 「今天 2 件事到点了」+ 晚上陪女儿（不催） | 陪伴不被打扰 |
| 老友 L 发动态 | 「你俩 3 周没联系了，要不要问候一句？」 | 关系不靠硬记 |
| 你说「帮我想想」 | Coop 才动手起草，平时不插嘴 | 不被推着走 |
| 夜里 | 「跑步又往后挪了，健身这件事在松动」 | 看清自己的趋势 |
| 状态不明时 | 「今天要不要把强度降一点？你说了算」 | AI 不替你做主 |
| 同框 | 公司的并购和家里的陪伴，在同一个地方 | 一个工具过完一天 |

## 由价值倒推的理想态要求

| 维度 | 理想态必须满足的要求 |
|------|---------------------|
| 本体建模 | 一切以「事」为注意力单位；消息/文件自动归并为事的状态变更；事携带类型(推进/存续) + 参与方；人携带通道状态 + 交付画像 |
| 治理 | 被动测态 always-on 且静默；主动推动 opt-in；存续型事默认不被推向完成态 |
| 推进 | 每个建议能诊断瓶颈在信息还是在人；对人相关的建议服务于关系，执行变好是副产品 |
| 协同（置信度） | 所有判断带置信度；低置信 → 弃权/移交；所有对外动作默认需人确认 |
| 统一性 | 同一引擎跑个人 ↔ 组织，切换的只是参与方构成 |
| 体验 | 主屏回答「现在需要我出手的什么事」，不是「有多少未读」；默认只呈现需要你的那几件 |
