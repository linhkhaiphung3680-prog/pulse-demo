## 一句话架构

**消息是燃料** → 经由**人这条通道**（信任/感受决定传递效果）→ 推动**事这副骨架**（从未明确到明确）。

身份是根事；今日是「需你介入」的视图；复盘是收敛的一种。

---

## 三本体

### 人 People（通道）

- 角色 / 与你和组织的关系
- 主观状态：信任 · 情绪/负荷 · 认同
- 参与的事 + 在每件事里的角色
- 交付画像：靠谱度 / 能扛模糊指令 vs 只能执行明确指令

### 事 Matters（骨架 · 注意力单位）

- 态：模糊 ⇄ 明确（连续）+ 类型：推进型 / 存续型
- 参与方（人 + 角色）
- 事树位置：母事 / 子事
- 瓶颈诊断：信息不清 还是 人不通
- 下一步 / deadline（仅推进型）

### 消息/输入 Inputs（燃料）

- IM · 邮件 · 会议转写 · 文件 · 在线文档
- 不是注意力单位，是「事的状态变更流」
- 每条被归并到事、标注涉及的人
- 标注：让事更明确 / 更模糊；是否含承诺 · 危机信号

## 拆除 → 重建

| 拆掉的旧框架 | 重建为 |
|-------------|--------|
| 收件箱作主屏 | 事主屏（「现在需要你介入的事」） |
| 今日 3 件事 · 硬上限 | 动态：此刻真正需要你介入的 N 件，其余 AI 在静默守着 |
| 北极星 / 主线 / 关系 / 时间 · 四轴 | 坍缩为 事(骨架)+人(通道)+消息(燃料)；身份 = 根事 |
| 复盘 = 唯一记忆写入入口 | 实时测态 + 归并为主；复盘降为收敛动作之一 |
| 关系 = 社交同心圆 | 人 = 事的通道（信任 / 负荷 / 认同） |
| 主动推送克制 | 两速：被动测态 always-on 静默 + 主动推动 opt-in |

## 理想态的 5 个核心界面（探索稿）

| 界面 | 角色 | 说明 |
|------|------|------|
| 事主屏 | 主屏（取代收件箱） | 按杠杆排「现在需要你介入的事」。每张卡：一句话态势 + 瓶颈是信息还是人 + 一个建议动作 + 落差预警 |
| 事详情 | 一棵事的全景 | 事树、参与方、态势时间线、瓶颈诊断、下一步 |
| 人 | 通道与执行者画像 | 他参与的事、交付记录、通道状态趋势；关于人的推断尤其保守 |
| 输入流 | 取代「待回消息」 | 事的状态变更流：每条已归并到事、标人、标态变化 |
| 推进面 | 推进一件事的动作面 | 给澄清/拆解/定标准草稿，或「谁的通道是瓶颈、怎么修」草稿；带置信度 |

> 注：[04-observability-first.md](04-observability-first.md) 在此基础上进一步激进删减为 2 个界面（Now + 信任审计）。

## 管理者的周一早上（走查）

| 时刻 | 体验 |
|------|------|
| 打开 | 事主屏：「本周 6 件事需要你介入」——不是 200 封未读 |
| 新能源并购 | 卡在人 · 建议你出面 15 分钟 · 落差：你和投资部口径不一致 |
| 物业 IPO 合规 | 3 子事 2 已明确，剩「关联交易披露」停滞 9 天 · 瓶颈在财务 · 建议推进动作 |
| 地产现金流 | 本周转明确态，无需你介入，已自动同步董事会口径 |
| 点开并购 | 事详情看事树 + 参与方 → 推进面给草稿 → 置信度高，你确认发出 |
| 新邮件进来 | 自动归并到「并购」事，标注让事更明确，无需你分拣 |

## 战略分叉

| 议题 | 说明 |
|------|------|
| B 端 vs 消费 | 面向管理者/B 端与消费 Persona 是重大分叉；可作为同一引擎的「工作模式」 |
| 同一引擎跑个人版 | 家里的「人/事/消息」与公司的「人/事/消息」是同一模型、不同参与方 |
| 第三方人状态推断 | 对第三人的敏感推断是最大隐私/伦理面，需明确边界 |
| 人是目的 | 对人相关的建议必须真心服务于人，执行变好是副产品 |
